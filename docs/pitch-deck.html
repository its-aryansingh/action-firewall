The problem

Everyone is building a faster button.

The instinct is to treat agentic payments as a checkout problem. The moment an agent holds a payment instrument, it stops being one.

1

Merchant

Unbounded chargeback liability. An AI buyer that overspends is a dispute the merchant loses.

2

Consumer

Runaway-spend fear. Nobody hands an autonomous agent an uncapped payment instrument.

3

Regulator

NPCI is building the Unified Agent Protocol precisely because delegation needs a standard.

What is missing is not a checkout. It is an authorization layer that is deterministic, auditable and revocable.

Track 01 asks for money actions that are “bounded and gated”. That phrase is the whole product.

Two records, deliberately separate

audit_log — append-only, written before the tool call, so a blocked attempt is as durable as a settled one.

spend_ledger — written only on a successful tool result; the mandate envelope is never optimistically debited.

Money attempted and money moved are different facts. A log that only records success is not evidence.

First principles

Why a mandate layer and not just a chatbot

“Why not multi-agent?”

Razorpay's own FTX26 position: for commerce, one well-instrumented agent with full context has fewer handoff failure modes and predictable latency. Multi-agent adds a second place for authority to leak.

“Why not prompt the model to respect the limit?”

A prompt is a request. A gate is a guarantee. Ours is a pure function with 22 tests, and it runs whether or not the model cooperates.

“What if Razorpay errors mid-checkout?”

Audit row written first, spend recorded only on success, shopper told nothing was charged. The envelope is never optimistically debited.

“How does this become a Razorpay product?”

It is the mandate service between Agent Studio and the payment tools: one row per delegated authority, one verdict per action, one log the risk team can underwrite.

We are not shipping a chatbot that can buy things. We are shipping the authorization primitive that makes an AI buyer underwritable.
